# niftic-app-starter

A GitHub template repo that produces every kind of app Niftic ships. It is a
**superset codebase plus a configure engine**: this repo carries all supported
variants, and a one-time `pnpm configure` prunes it down to one concrete app
based on `niftic.app.yml`.

> If `niftic.app.yml` has a `generated:` block, this repo is already configured —
> the sections below about variants and configure no longer apply, and `variants/`
> and `scripts/configure/` are gone. Work on it like any normal SvelteKit app.

Detailed rules and workflows live in the `niftic-app` skill
(`.claude/skills/niftic-app/`). Read that before adding features.

## Stack

SvelteKit 2 + Svelte 5 (runes only), TypeScript strict, Tailwind v4 (no config
file — tokens live in `src/app.css`), Zod 4 + sveltekit-superforms, Vitest,
Playwright. pnpm, Node 24.

Per-profile pieces (Drizzle, Better Auth, supabase-js, Resend, R2) arrive via
`variants/` at configure time, so an app only ever carries what it uses.

## Commands

```
pnpm configure       # one-time: manifest -> concrete app (deletes itself)
pnpm dev             # dev server
pnpm check           # svelte-check
pnpm lint            # prettier --check && eslint
pnpm format          # prettier --write
pnpm test:unit       # vitest
pnpm test:e2e        # playwright
```

## Where things live

```
src/lib/components/   hand-rolled UI primitives (no component library — see below)
src/lib/server/       env, logger, and the adapters (email/, storage/, db/, auth/)
src/lib/app-config.ts GENERATED by configure — this app's profile + capabilities
src/routes/           (site) public · (app) authed · admin · api
scripts/configure/    the engine (deleted by configure)
variants/             overlay trees (deleted by configure)
```

## Rules that hold everywhere

- Mutations go through SvelteKit form actions with Zod validation. Authorization
  is re-checked server-side in every action — never trust a hidden field or a
  client-side guard.
- Never call a database, Resend, R2, or any service key from browser code.
- All email goes through `sendEmail()`. All uploads go through the storage port
  and signed URLs. ESLint enforces both boundaries.
- Typed env comes from `$lib/server/env`. `process.env` is banned elsewhere.
- Migrations are always committed.
- Never add a second auth library, ORM, validation library, or a component
  library. The primitives in `src/lib/components/` are the component library.
- Never print or commit credentials.

## Changing the app's shape

Edit `niftic.app.yml` and re-run configure **only before** the repo is
configured. Afterwards, switching profile is a documented manual migration, not
a command — `configure --force` prints the path rather than re-running.

## Honesty about verification

Borrowed from `niftic.com/CLAUDE.md`, and it applies here too: "verified" in a
commit message must mean you actually ran it. If you checked the code but not
the running app, write "verified in code, not in browser". If a preset's CI lane
is red or unrun, say so rather than implying the matrix is green.
